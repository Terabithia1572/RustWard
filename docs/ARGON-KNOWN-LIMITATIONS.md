# ARGON Known Technical & Security Limitations

Each limitation below reflects a genuine architectural, protocol, or operating-system boundary verified during the ARGON audit. None are hidden behind UI status toggles.

| ID | Category | Limitation | Technical Cause | Operational Mitigation |
|---|---|---|---|---|
| **AL-01** | Hardware Identity | **USB & SCSI descriptors are unauthenticated (`authenticated = false`).** | Standard USB Mass Storage (`BOT` / `UASP`) provides no cryptographic device certificate or challenge-response; firmware self-reports `VID`, `PID`, serial, and 8-byte SCSI `INQUIRY` vendor strings. | Cross-check `VID` vs `INQUIRY` (Phase 3 `ConflictingIdentifiers` fail-closed deny); enforce physical custody/issuance of approved media; audit every connection. |
| **AL-02** | Target Hardware | **TÜBİTAK / BİLGEM / SIR II hardware identifiers are unresolved.** | No physical SIR II device has been inspected; identifiers must never be guessed or invented, and encrypted tokens may change PnP presentation after PIN unlock. | Kept `enforceable = false` in catalog (fail-closed `DENY` with explicit warning). Inspect genuine SIR II hardware pre- and post-unlock when available (Stage B). |
| **AL-03** | Target Hardware | **SanDisk allowlist rules have not yet been tested against physical SanDisk hardware in the VM.** | Only the Kingston (`0951:1666`) and generic `VendorC` (`346D:5678`, ASELSAN-labelled) sticks were physically attached; `346D:5678` is **not** SanDisk. | Obtain genuine SanDisk BOT and UASP drives to confirm `USBSTOR\DiskSanDisk_` / `SCSI\DiskSanDisk_` matching across models (Stage B). |
| **AL-04** | Generic Bridges | **Products using generic USB-SATA/NVMe bridge strings (`Generic`, `VendorC`, `ASMT`, `JMicron`, `Realtek`, `SMI`, `Phison`) cannot be allowlisted at brand level.** | Allowing `USBSTOR\DiskASMT____` would authorize **every** enclosure using an ASMedia bridge regardless of drive brand. | Rejected fail-closed (`GenericVendorIdentity`). Any exception would have to be pinned to a specific device instance ID (`AllowInstanceIDs`) by explicit administrative policy. |
| **AL-05** | Windows PnP | **Non-retroactive `DiskDrive` class prevent does not block USB drives installed before policy activation.** | Windows `DenyDeviceClasses` with `Retroactive = 0` governs new driver installs/updates only; enabling `DenyDeviceClassesRetroactive = 1` risks disabling the OS boot disk (`Microsoft warning`). | Use narrow device-specific `DenyDeviceIDsRetroactive = 1` rules, or use `Uygulama Hazırlığı` (`assess-installed`) to review and manually uninstall prior unauthorized USB `DiskDrive` devnodes in Device Manager before/after enabling the non-retroactive profile. |
| **AL-06** | System Maintenance | **An active `DiskDrive` setup-class restriction also blocks newly added internal disks, VHD/VHDX mounts, Storage Spaces, and boot-disk controller/slot migrations.** | All block disks share setup class `{4d36e967-e325-11ce-bfc1-08002be10318}`; baseline `AllowInstanceIDs` protects only the existing internal disk's exact instance path. | Suspend/remove the class restriction before hardware controller changes, disk replacements, or VHD mounts; keep WinRE offline recovery instructions (`ARGON-ROLLBACK-PLAN.md` Tier R4) on hand. |
| **AL-07** | Scope | **Installation denial (`Code 1` / `Code 28`) is not granular per-brand read-only control and does not automatically cover non-`DiskDrive` classes (`WPD`/MTP, `CDROM`).** | Built-in `Removable Storage Access` (`RemovableStorageDevices`) is class-wide (cannot allow SanDisk while denying Kingston) and misses USB SSDs/HDDs reporting `RMB = 0` (Fixed Disk). | Report installation denial honestly (`WINDOWS ENGELİ DOĞRULANDI` + `ERİŞİM DOĞRULANAMADI` qualifier for untested non-disk/raw paths); flag `UsbPortableDevice` and `UsbStorageOtherType` explicitly. |
| **AL-08** | Automation Gate | **Automated OS policy writing is disabled (`ACTIVATION_ENABLED = false`).** | Blocked by Phase 6 safety review (`B1`); proper Local GPO persistence requires COM `IGroupPolicyObject` (`Registry.pol`) and separate owner sign-off. | Administrator applies reviewed checklists via `gpedit.msc` + `gpupdate /force`; RustWard prepares baselines, verifies exact registry state, observes live `CM_PROB_*` denials, and verifies rollback. |
| **AL-09** | Privilege Model | **Local Administrators can modify Group Policy, stop `RustWardService`, or alter local files.** | Inherent to Windows local administrator authority; SQLite hash chains and Event Log checkpoints are tamper-evident, not tamper-proof against `SYSTEM`/Admin. | Run workstation users as Standard Users; protect BIOS/UEFI + BitLocker; export signed/hashed audit checkpoints periodically to offline write-once media. |
| **AL-10** | Packaging & Signing | **Executables and MSI are Authenticode-unsigned; catalog updates do not overwrite customized live SQLite catalogs on MSI upgrade.** | Code-signing certificates live outside the repository; MSI preserves `%ProgramData%\RustWard\rustward.db` across upgrades to protect local policy history and audit chains. | Verify SHA-256 hashes prior to VM/offline installation; sign artifacts in release pipeline; apply new catalog entries through versioned admin edits or signed offline catalog import. |
